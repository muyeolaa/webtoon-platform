1 파일명은 케밥 케이스 (naver-crawler.service.ts ) 이름만봐도 기능을 알수있도록

2. 클래스 이름(코드 내부)은 파스칼 케이스(PascalCase)로 작성합니다.
   파일명은 소문자+하이픈이지만, 그 파일 안에 들어가는 코드의 진짜 이름은 첫 글자를 대문자로 씁니다.
   예: naver-crawler.service.ts 파일 안에는 export class NaverCrawlerService { ... } 라고 적습니다.

==========================================
이 명령어들이 실제 회사에서 어떻게 연결되는지 흐름을 보면 이해가 확 되실 겁니다.

[내 컴퓨터] npm run dev를 켜놓고 열심히 코딩을 합니다.

[내 컴퓨터] 기능 구현이 끝나면 npm run lint를 쳐서 에러가 없는지 쓱 검사하고 깃허브에 코드를 올립니다.

[운영 서버] 코드를 넘겨받은 실제 회사 서버(AWS 등)가 npm run build를 실행해서 코드를 단단하게 압축합니다.

[운영 서버] 압축이 끝나면 npm run start를 실행해서 실제 고객들에게 최적화된 속도로 서비스를 제공합니다!

그래서 초보 시절에는 dev 하나만 주구장창 쓰게 되지만, 프로젝트를 진짜 인터넷 세상(서버)에 올릴 때가 되면 build와 start의 소중함을 뼈저리게 느끼게 된답니다. 😎
